### 1.1 三层职责

```
┌─ 语义层 ────────────────────────────────────────────────┐
│ nlu.py       自然语言 → 有序意图列表；app 名称匹配        │
│ config       34 份 YAML：每个 app 每个 behavior 的步骤链   │
└──────────────────────────┬──────────────────────────────┘
┌─ 编排层 ─────────────────▼──────────────────────────────┐
│ behavior_runner.py  意图→行为解析、时间窗、模板随机、分派  │
│                     、19 个 step 原语、收益识别           │
└──────────────────────────┬──────────────────────────────┘
┌─ 设备层 ─────────────────▼──────────────────────────────┐
│ device_session.py  连接/冷启/等稳定/回顶层/安全 dump      │
│ locator.py         四级定位降级 + 知识库 + 视觉兜底       │
│ human*.py          拟人动作；vision.py 视觉；landing 校验  │
└─────────────────────────────────────────────────────────┘
```

三层之间只有一个方向：**上往下调用，下往上只回 `True/False/None`**。设备层不知道"签到"是什么，
编排层不知道 u2 的 API 长什么样，语义层不碰设备。这条边界基本守住了，唯一渗漏是
`behavior_runner._step_click_point` 里直接算了 `win_wh` 并调 `human.tap`——它同时做了"定位"和"点击"两件事。

### 1.2 一次执行的完整时序

以 `--task "去趣头条签到"` 为例：

```
main.py
 ├ parse_args → load_config("config.yaml")
 │    └ config_loader: apps 为空 → 扫 config/apps/*.yaml → 34 个 app 合并
 ├ nlu.parse_intents("去趣头条签到")        → [("sign","签到")]
 ├ nlu.match_app("去趣头条签到", apps)      → 趣头条（别名"趣头条"命中）
 └ Executor(serial, human, recorder, cfg)
      └ run_app_flow(app_cfg, intents)
           ① _open_app(pkg, reset=launch_reset)     冷启动，等页面稳定
           ② for intent in intents:
                bid = _resolve(app_cfg, intent)       intent_map 优先，否则同名
                _window_open(bid_cfg)                 作息/时间窗门控，窗外记 BLOCKED
                actions = _pick_variant(...)          多模板随机 + 排除上次用过
                _run_actions(actions)
                   └ 每步 _dispatch_step:
                        human.delay()                 0.6–2.2s 随机停顿
                        human.maybe_wander(d)         6% 概率乱逛
                        _run_kind(act)                按 type 分派
                           └ 失败 → 记 WARN + human.think() + 继续下一步
           ③ 收益识别（reward 步）写入 recorder / sqlite
```

**关键取舍**：单步失败不中断。理由是一条链里"某步 miss"是常态（开屏广告、灰度活动页、
网络慢），中断会让整个 app 白跑；代价是失败被"摊平"了——所以才有 `sign_evidence.py` 这套
独立的成功判定，不依赖执行流是否走完。

### 1.3 定位：为什么需要四级降级

真机上"找到并点中一个按钮"的难度被严重低估。项目踩到的三类页面：

| 页面类型 | 特征 | 应对 |
|---|---|---|
| 标准原生页 | a11y 树完整，`text=` 可选中 | u2 selector（②） |
| H5 / WebView | dump 只有十几个节点、无任何文案（快手任务中心实测 17 节点） | 视觉兜底（④）或坐标（⑤） |
| 自绘视图（如 `BulletContainerActivity`） | XML 里有 text 节点，但 `text=` 选择器匹配不到；树常为空 | 坐标（⑤）+ `expect` 校验 |

四级降级的实际顺序与代价：

| 级 | 手段 | 命中率 | 代价 | 失败时 |
|---|---|---|---|---|
| ① | 元素知识库候选 | 高（历史成功过的 selector） | 0 | 轮换 alternatives，连败 3 次置 disabled |
| ② | u2 selector | 中高 | ~1s 轮询到 timeout | 进 ③ |
| ③ | `click_first` 多候选 + 全局词表自搜寻 | 中 | 每候选一次 dump，慢 | 进 ④ |
| ④ | 视觉兜底：模板匹配 → VLM | 中低（VLM 本机常 90s 超时） | 秒级~90s | 进 ⑤ |
| ⑤ | `click_point` 比例坐标 | 取决于校准 | 0 | 有 `expect` 则校验落地，否则**静默走错页** |

第 ⑤ 级是最危险的：坐标是盲点，偏 80px 就静默走错页，日志只有「滚动 4 页未找到」。
所以 2026-10-23 加了 `landing.py` 的**落地校验**（5 信号投票，全过才算过、全跳过算未知不阻断），
并要求坐标点击尽量配 `expect`。

> 这也是评审问题 Q1 的背景：既然"点没点中"这么难保证，把成功判定建在日志文本上是否足够？

### 1.4 失败分类（决定了日志与体检口径）

| 现象 | 归类 | 谁记录 | 是否阻断 |
|---|---|---|---|
| 选择器/文案没找到 | **miss** | `_last_fail` → WARN「步骤失败: 未找到文本按钮: X」 | 否，继续下一步 |
| 硬断言不满足 | **error** | `StepError` → WARN | 否，跳过该步继续 |
| 点击后落地校验不过 | **degraded** | WARN「落地校验未通过」 | 否，可配 retry 重点击 |
| 弹窗清扫无弹窗 | **正常态** | INFO「屏幕干净，无需处理」 | 否（曾被误判为失败，已修） |
| 时间窗关闭 | **BLOCKED** | WARN | 是，跳过整个行为 |
| 进程超时 / 非零退出 | **fatal** | 体检判 RED | 是 |

体检脚本（`temp/health_check.py`）把上述信号映射成 RED/YELLOW/GREEN，并**强制分成两列**：
「链路判定」与「确认点到签到按钮」。因为 GREEN 只说明"没有失败信号"，
一个静默 miss 的步骤同样不留失败字样——这正是 `sign_evidence.py` 存在的理由。

### 1.5 拟人与反检测（`human.py` / `human_trajectory.py` / `docs/ANTI_DETECTION.md`）

| 手段 | 实现 | 目的 |
|---|---|---|
| 点击抖动 | `tap_jitter_px: 12`，坐标高斯扰动 | 不落在同一点 |
| 动作停顿 | `delay_between_actions: [0.6, 2.2]` 均匀随机 | 不像机器节拍 |
| 分心乱逛 | `wander_probability: 0.06` | 行为间隙有"人味" |
| 手势轨迹 | 贝塞尔 + 垂直抖动 σ=1.2 + 缓入缓出 + 25% 过冲 | 滑动不是直线 |
| 误触-回退 | `mistake_prob: 0.05`：先点附近错位，再点正确位置 | 模拟手滑 |
| 限流长停 | `cooldown_every: 12` 次点击后停 14–26s | 打断机械节奏 |
| 作息窗 | `wake_window 07:30–23:00` + 启动抖动 0–600s | 不在凌晨跑 |
| 路径随机 | 同一 behavior 多模板，按 `variant_prob: 0.8` 排除上次用过的那套 | 每次路径不同 |
| 验证码 | `captcha_slider.py`：缺口识别 + 拟人拖拽；失败后 300s 会话级冷却 | 不猛点重试 |

**边界（红线）**：资金类动作只到"看到余额"；弹窗清扫命中「提现/支付/银行卡/实名」等文案即熔断
并禁用 BACK（按 BACK 消化确认弹窗 = 替用户确认资金操作）。

### 1.6 配置语言：实际长什么样

一份 app 配置 = `name` / `package` / `aliases` / `intent_map` / `behaviors`。
`behaviors[bid]` 有两种形态：

```yaml
behaviors:
  sign:                      # 形态 A：直接是步骤列表
  - type: click_text
    text: 签到

  watch:                     # 形态 B：带时间窗 / 多模板
    window: {start: "08:00", end: "23:30"}
    actions:
    - [ ...模板1... ]
    - [ ...模板2... ]        # 每次随机挑一套，避免路径固定
```

15 个规范 step 类型：

| 类型 | 作用 | 用量 |
|---|---|---|
| `click`（`by: text/id/desc`） | 统一点击原语，本次新增 | 新配置用 |
| `click_text` / `click_id` / `click_desc` | 点击的旧名（别名） | 41 / 2 / 2 |
| `click_first` | 多候选依次试 + 词表自搜寻 | 143 |
| `click_point` | 比例坐标，可绑 images/vlm_prompt + `expect` | 118 |
| `swipe`（`natural`/`straight`） | 滑动，默认走人类轨迹 | 24 |
| `swipe_natural` | 旧名（别名） | 0 |
| `wait` / `think` | 固定等待 / 拟人停顿 | 31 / 103 |
| `any_of` / `random` | 条件分支 / 随机分支 | 48 / 0 |
| `scroll_to` | 滚到文本并点击 | 1 |
| `back` / `home` | 返回 / 回桌面 | 1 / 0 |
| `dismiss_popups` | 弹窗清扫 | 1 |
| `reward` | 收益数字识别（正则命名组） | 25 |
| `ensure` | 硬断言 | 1 |
| `captcha` | 滑块（预留） | 0 |

**没有的东西**（评审时请重点判断要不要补）：变量/参数化、循环、显式错误处理分支、
schema 校验（现在是 `validate_config` 的轻量检查 + 命名测试）、跨 app 复用（同一套链路 34 份拷贝）。

### 1.7 关键设计决策（ADR 速记）

| 决策 | 选择 | 放弃的替代 | 理由 |
|---|---|---|---|
| 配置 vs 代码 | 全部配置驱动 | 每个 app 一个 Python 类 | 加 app 不改代码；但代价是 YAML 复杂化 |
| 单步失败 | 记 WARN 继续 | 抛异常中断 | 链里 miss 是常态 |
| 视觉兜底 | 显式 `allow_vision` 参数链 | 实例标志位 | 标志位在异常后留脏状态 |
| 老 type 名 | 永久别名 | 批量改写配置 | 541 步是实机资产，不赌 |
| 成功判定 | 独立模块 grep 日志 | 依赖执行流返回值 | 返回值只说"没崩"，不说"点中了签到" |
| 定位 | 四级降级 + 坐标兜底 | 只信 a11y | 自绘/H5 页面上 a11y 树为空 |
| 门面 | 三重多继承 | 组合 + 显式委托 | 保住 422 个对实例打桩的测试（代价见 Q3） |
| 依赖缺失 | 静默降级（`try/except ImportError`） | 启动即失败 | 让"只拷走部分文件"能跑（代价见 Q5） |

### 1.8 已知技术债（我自己的清单，可与你的发现对照）

1. `_step_click_point` 混了定位与点击两件事（见 §1.1）。
2. `_extras_cache` / `_current_bid` / `_variant_last` 等实例属性散落在三个 mixin 里，无统一状态容器。
3. `landing.py` / `captcha_slider.py` 对 cv2 静默降级 → 用错环境时"看起来在跑，其实没校验"。
4. `miniyaml.py`（484 行）是自写的零依赖 YAML 解析器，只在没有 PyYAML 时启用；
   两条解析路径并存 = 两套行为，测试只覆盖了部分嵌套场景。
5. 体检脚本在 `temp/` 下（未进包管理），是事实上的关键工具但没有测试。
6. 34 份配置里同一条链路被抄了多份，没有 include/复用机制。
7. `sign_evidence` 依赖日志措辞，措辞一改判定静默全灭（无自检）。

## 2. 代码：核心模块全文

> 这些文件都不大、彼此独立，是「判定口径 / 意图解析 / 门面 / 配置加载 / 定位择优」五件事的全部实现。建议**逐行看**，它们是整套设计的最小可判定面。

### 2.1 `sign_evidence.py` —— 「签到按钮确实被点过吗」的唯一判定口径

全项目只有这一处回答「这次算不算签到成功」。它只做**日志文本复核**，不碰设备、不依赖任何执行层对象，因此可离线重判历史日志。

**`sign_evidence.py` 第 1–76 行**

```python
# -*- coding: utf-8 -*-
"""sign_evidence.py - 「签到按钮确实被点过了吗」的单一判定口径。

2026-10-25 用户定的判定规则：

    **只有复核过「签到按钮确实被点过了」，才认为已经成功签到。**

常见误用（本模块就是为堵这些口子而存在）：
    - 任务执行完毕 / 流程跑完        → 只说明链没崩，不说明点中了签到按钮
    - 健康体检 GREEN                 → 只说明没有失败信号
    - 日志里没有「步骤失败」字样      → 静默 miss 的步骤一样不留失败字样
    - 顶部金币计数变多                → 每会话重置，且可能来自别的行为

认可的凭据只有两类：
    1. 点击凭据：日志里出现点击行，且该行点中的文案命中签到类词表
    2. 终态凭据：重新打开 app 显示已签状态（由调用方离线核验，不在本模块内）

两类都没有 → 一律「未确认」。宁可少记成功，不可多记。

用法：
    from sign_evidence import signed_evidence
    ok, line, kind = signed_evidence(log_text)
"""
import re

__all__ = ["SIGN_WORDS", "CLICK_LINE", "signed_evidence", "SIGN_EVIDENCE_RULE"]

# 签到类文案词表。命中即认为该次点击的语义对象是「签到按钮」。
# 注意：导航类入口（任务 / 任务中心 / 赚钱 / 福利中心 / 我的）**故意不收**——
# 点中它们只代表进了门，不代表点了签到按钮。
SIGN_WORDS = (
    "签到", "立即签到", "签到领取", "领金币", "领现金", "赚现金", "开宝箱",
    "福利", "早起打卡", "每日签到", "签到奖励", "点金币", "金币签到",
)

# 三种「真的点了某个东西」的日志行。
#   - 多候选命中并点击: (kind)值     —— click_first 命中候选
#   - 点击文本: XXX                  —— click_text 命中
#   - 视觉兜底点击成功: 描述 -> 坐标  —— 模板/VLM 命中
# 故意**不含**「点击坐标: (x,y)」：那是盲点，可能点在任何东西上，
# 拿它当签到凭据等于没有凭据（2026-10-25 悟空踩过的坑）。
CLICK_LINE = re.compile(
    r"(多候选命中并点击|点击文本|视觉兜底点击成功)[^\n]*")

SIGN_EVIDENCE_RULE = (
    "只有复核过「签到按钮确实被点过了」，才认为已经成功签到。"
    "任务执行完毕 / 体检 GREEN / 无「步骤失败」/ 金币计数都不算凭据。"
)


def signed_evidence(log_text):
    """从一段日志里复核「签到按钮是否确实被点过」。

    Args:
        log_text: 一次行为执行的完整日志文本（多行字符串）。

    Returns:
        (confirmed, evidence_line, kind)
            confirmed     True=有点击凭据；False=未确认
            evidence_line 凭据所在日志行（未确认时为 None）
            kind          凭据类型：多候选命中 / 文本命中 / 视觉兜底命中
    """
    if not log_text:
        return False, None, None
    for line in log_text.splitlines():
        if not CLICK_LINE.search(line):
            continue
        if any(w in line for w in SIGN_WORDS):
            if "多候选命中并点击" in line:
                kind = "多候选命中"
            elif "视觉兜底点击成功" in line:
                kind = "视觉兜底命中"
            else:
                kind = "文本命中"
            return True, line.strip(), kind
    return False, None, None
```

### 2.2 `nlu.py` —— 自然语言 → 有序意图列表 + app 匹配

关键词规则引擎，无模型。`parse_intents` 长词优先，`match_app` 六级收窄。

**`nlu.py` 第 1–140 行**

```python
# -*- coding: utf-8 -*-
"""
nlu.py - 自然语言行为解析器
把用户的一句自然语言（如 "帮我去XX签到并看视频，然后提现"）
解析成有序的【意图列表】，再在配置阶段绑定到具体 app 的行为模板。
采用关键词规则引擎：可维护、可解释、无需重模型。
"""
import re

# 内置意图 -> 行为 ID 词典（app 配置中若自定义 intent_map 则优先）
# 2026-10-25 整理：
#   ① 新增 gift（快马的「白拿礼物」原是中文自定义 behavior 名，现收编为标准意图）；
#   ② growth 删掉「签到领」—— _ORDERED_ITEMS 长词优先，「签到领」会抢在
#      「签到」之前命中，导致「签到领金币」被解析成 growth 而不是 sign；
#   ③ reserve 正式启用（抖音火山版没有签到只有预约，intent_map: sign→reserve）。
DEFAULT_INTENT_MAP = {
    "sign":    ["签到", "每日签到", "打卡", "签到打卡"],
    "reserve": ["预约打卡", "预约签到", "预约"],
    "watch":   ["看视频", "刷视频", "看广告", "刷广告", "看任务视频", "视频任务"],
    "withdraw": ["提现", "提钱", "兑换红包", "提收益"],
    "bonus":   ["领红包", "领金币", "领取奖励", "领任务奖励", "领积分"],
    "collect": ["收集", "收取能量", "喂鸡", "浇水", "收取金币"],
    "growth":  ["浇花", "施肥", "升级", "做任务"],
    "gift":    ["白拿礼物", "白拿", "免费领", "领礼物"],
    # `open` 是部分 App（百度极速版、海马畅听）唯一/主要的配置行为名，
    # 之前没有对应关键词，导致「百度极速版」只能用回退意图（sign）而被跳过。
    "open":    ["打开", "启动", "开启应用", "开应用"],
}

# 匹配顺序：长词优先，避免"签到"吞掉"预约签到"这类更长词组
_ORDERED_ITEMS = sorted(
    [(kw, intent) for intent, kws in DEFAULT_INTENT_MAP.items() for kw in kws],
    key=lambda x: len(x[0]), reverse=True,
)


def parse_intents(natural_text: str) -> list:
    """从自然语言中提取有序意图。返回 [(intent_id, 命中的关键词), ...]，保持原文出现顺序"""
    text = natural_text or ""
    hits = []
    for kw, intent in _ORDERED_ITEMS:
        if kw in text:
            # 记录关键词在原文中的位置，用于保持顺序
            idx = text.index(kw)
            hits.append((idx, intent, kw))
    # 去重（同一意图只保留命中一次）
    seen = set()
    ordered = []
    for idx, intent, kw in sorted(hits, key=lambda x: x[0]):
        if intent in seen:
            continue
        seen.add(intent)
        ordered.append((intent, kw))
    return ordered


def match_app(text: str, apps_cfg: list):
    """在自然语言或 --app 参数中匹配配置的 app。
    返回 (匹配的 app dict, None) 或 (None, 匹配失败原因)。

    匹配优先级（逐级收窄，避免"京东理财"被"京东"抢先命中）：
      1. 包名精确
      2. 名称精确
      3. 别名精确
      4. 最长子串（名称/别名出现在文本里；或用户输入是名称的片段）
      5. 包名子串
      6. 数字序号

    历史缺陷：旧实现按 apps 配置顺序做「别名 in 文本」判断并立即返回，
    由于"京东"排在"京东理财"之前，`--app 京东理财` 会误命中"京东"，
    任务被发到错误的 app。故改为先精确后最长匹配。
    """
    raw = (text or "").strip()
    t = raw.lower()
    if not apps_cfg:
        return None, "配置中没有定义任何 app"
    if not t:
        return None, "未能识别出 app（请用 --app 指定，或在意向句里带上 app 名）"

    def _name(app):
        return (app.get("name") or "").strip()

    def _aliases(app):
        return [str(a).strip() for a in (app.get("aliases") or []) if str(a).strip()]

    # 1) 包名精确
    for app in apps_cfg:
        pkg = (app.get("package") or "").strip().lower()
        if pkg and pkg == t:
            return app, None

    # 2) 名称精确
    for app in apps_cfg:
        if _name(app).lower() == t:
            return app, None

    # 3) 别名精确
    for app in apps_cfg:
        for alias in _aliases(app):
            if alias.lower() == t:
                return app, None

    # 4) 最长子串匹配
    best_score, best_idx, best_app = -1.0, -1, None
    for i, app in enumerate(apps_cfg):
        tokens = ([_name(app)] if _name(app) else []) + _aliases(app)
        for tok in tokens:
            tl = tok.lower()
            if not tl:
                continue
            if tl in t:
                # 用户输入里包含该 app 名/别名：以命中长度为准，越长越具体
                score = float(len(tl))
            elif t in tl and len(t) >= 2:
                # 用户输入是名称的片段（简称/漏字），弱化计分
                score = len(t) * 0.5
            else:
                continue
            if score > best_score:
                best_score, best_idx, best_app = score, i, app
    if best_app is not None:
        return best_app, None

    # 5) 包名子串
    for app in apps_cfg:
        pkg = (app.get("package") or "").strip().lower()
        if pkg and pkg in t:
            return app, None

    # 6) 数字序号（如 "app 1" / "1号app"）
    m = re.search(r"(\d+)\s*(?:号)?\s*(?:app|应用)?", t)
    if m:
        idx = int(m.group(1)) - 1
        if 0 <= idx < len(apps_cfg):
            return apps_cfg[idx], None
    return None, f"在配置中未找到匹配的 app（当前共 {len(apps_cfg)} 个）"

# 注：意图 → behavior 的解析在 behavior_runner.Executor._resolve（唯一实现）。
# 此处原有一份 resolve_behavior 与它逐行相同且全仓库无人调用（2026-10-25
# 清理死代码时删除）—— 两处相同逻辑必然漂移，只保留执行层那一份。
```

```python
import os
import re

BASE_DIR = os.path.dirname(os.path.abspath(__file__))
DEFAULT_APPS_DIR = os.path.join(BASE_DIR, "config", "apps")


def safe_app_name(name):
    """App 名转安全文件名：非字母/数字/下划线/中文字符/连字符 → 下划线。"""
    s = re.sub(r"[^\w\u4e00-\u9fff-]+", "_", str(name).strip())
    return s or "app"


def _apps_dir(cfg, base_dir=None):
    d = cfg.get("apps_dir") or DEFAULT_APPS_DIR
    if base_dir and not os.path.isabs(d):
        d = os.path.join(base_dir, d)
    return d


def _load_yaml(path):
    try:
        import yaml
    except ImportError:  # 无 PyYAML 时用内置零依赖解析器兜底
        import miniyaml as yaml
    with open(path, "r", encoding="utf-8") as f:
        return yaml.safe_load(f) or {}


def load_config(path):
    """加载主配置；apps 段非空 → 旧单文件原样返回；否则拼接 apps_dir。"""
    if not os.path.exists(path):
        raise FileNotFoundError(f"配置文件不存在: {path}")
    cfg = _load_yaml(path)
    if cfg.get("apps"):
        return cfg
    apps_dir = _apps_dir(cfg, os.path.dirname(os.path.abspath(path)))
    merged = dict(cfg)
    merged_apps = []
    if os.path.isdir(apps_dir):
        for fn in sorted(os.listdir(apps_dir)):
            if not fn.endswith((".yaml", ".yml")):
                continue
            app = _load_yaml(os.path.join(apps_dir, fn))
            if app:
                merged_apps.append(app)
    merged["apps"] = merged_apps

def app_config_path(app_name, cfg=None, base_dir=None):
    """写回工具解析 App 级配置文件路径。

    拆分文件名为 `<序号>_<safe_name>.yaml`：先在 apps_dir 里按 safe_name
    扫描精确匹配；找不到时回退到拼接路径（兼容未拆分的旧文件名）。
    """
    apps_dir = _apps_dir(cfg or {}, base_dir or BASE_DIR)
    safe = safe_app_name(app_name)
    if os.path.isdir(apps_dir):
        for fn in sorted(os.listdir(apps_dir)):
            if not fn.endswith((".yaml", ".yml")):
                continue
            base = fn[:-5]
            if base == safe or base.split("_", 1)[-1] == safe:
                return os.path.join(apps_dir, fn)
    return os.path.join(apps_dir, safe + ".yaml")


def latest_config_mtime(path):
    """主文件 + apps 目录下所有 App 文件的最大 mtime（webui 缓存失效用）。"""
    mtimes = []
    if os.path.exists(path):
        mtimes.append(os.path.getmtime(path))
    try:
        cfg = _load_yaml(path) if os.path.exists(path) else {}
        apps_dir = _apps_dir(cfg, os.path.dirname(os.path.abspath(path)))
        if os.path.isdir(apps_dir):
            for fn in os.listdir(apps_dir):
                fp = os.path.join(apps_dir, fn)
                if os.path.isfile(fp):
                    mtimes.append(os.path.getmtime(fp))
    except Exception:
        # 主文件解析失败时至少回退到文件自身 mtime，不让缓存失效吞掉错误
        pass
    return max(mtimes) if mtimes else 0
```

```python
def _has_marker_standalone(label, m):
    """标记是否以「独立词语」身份出现（而非营销文案的构词成分）。

    ASCII 标记（'?'）直接子串判定。中文标记看邻字：
      - 多字疑问/说明词（'什么是'/'如何'/'规则'…）本身即强信号，
        仅当它同时是 target 的一部分时豁免；
      - '知'/'断' 这类单字级易撞标记要求至少一侧非汉字粘连，
        排除「…早知道」「…不断领」等构词误伤。
    """
    if m.isascii():
        return m in label
    start = 0
    while True:
        i = label.find(m, start)
        if i < 0:
            return False
        prev_c = label[i - 1] if i > 0 else ""
        next_c = label[i + len(m)] if i + len(m) < len(label) else ""
        glued = (bool(_CJK.match(prev_c)) if prev_c else False) and \
                (bool(_CJK.match(next_c)) if next_c else False)
        if not (len(m) == 1 and glued):   # 单字被两侧汉字夹住 -> 构词成分
            return True
        start = i + 1


def overlen_limit(target):
    """旧版长度阈值的等价函数（保留口径：max(len+6, len*3)）。"""
    return max(len(str(target)) + 6, len(str(target)) * 3)


def is_noise_label(label, target=""):
    """超长候选里甄别「绝不可能是按钮」的句式。

    判定：含疑问/说明/通知标记（独立成词才算，target 自带的字符豁免）；
    或不含目标词且以标点收尾的说明性长句。
    """
    label = str(label or "")
    t = str(target or "")
    if any(_has_marker_standalone(label, m) for m in _NOISE_MARKERS
           if m not in t):
        return True
    if t not in label and label[-1:] in ("，", ",", "。", "."):
        return True
    return False


def score_entry(entry, target, kind, screen_h=0, screen_w=0, zone=None):
    """单条目打分（纯函数）。entry = {label, clickable, top, left?, right?}。

    返回 (score, overlong_nonclickable)。overlong 标志供上层甄别兜底用，
    不影响分值语义。kind 目前只对 text/desc 做长度惩罚（id 无长度概念）。
    """
    label = str(entry.get("label") or "")
    t = str(target)
    clickable = bool(entry.get("clickable"))
    try:
        top = int(entry.get("top") or 0)
    except (TypeError, ValueError):
        top = 0

    if label == t:
        score = 1000
    else:
        # 旧版：100 - min(90, |Δlen|*3)，且含词/不含词候选同池混排。
        # 新版两条公理（由 test_plausible_floor_excludes_salvage_zone 锁定）：
        #   A1 含目标词的候选恒可信：最差 100-60+80=120 > floor；
        #   A2 不含目标词的非可点候选恒不可信：最高 100-0-90=10 < floor，
        #      即便 clickable(+50)=60 仍 < floor —— u2 contains 匹配到的
        #      不含词节点几乎总是说明句/背景文字，保守拒配符合旧版倾向。
        score = 100 - min(_LEN_DIFF_CAP, abs(len(label) - len(t)) * _LEN_DIFF_STEP)
        if t and t in label:
            score += _CONTAINS_BONUS
        else:
            score -= _NO_TARGET_PENALTY
    if clickable:
        score += 50

    # 导航词位置合理性：中部假命中扣分、底部带内加分（软先验，不硬过滤）
    if str(t).strip() in NAV_LABELS and screen_h:
        score += 120 if top >= NAV_BAND_Y * screen_h else -120

    # 第3步：位置先验 zone 加分（缺坐标/未知屏尺寸 -> 该条目中性）
    zone_bonus = _ZONE_BONUS.get(zone)
    if zone_bonus and screen_h and (zone != "right_edge" or screen_w):
        try:
            if zone in ("tab_zone", "top_right"):
                ok_zone = (top >= ZONE_BOTTOM_BAND * screen_h
                           if zone == "tab_zone"
                           else top <= ZONE_TOP_BAND * screen_h)
            else:
                ok_zone = True
            xc = None
            if zone in ("top_right", "right_edge"):
                if entry.get("left") is not None and entry.get("right") is not None:
                    xc = (int(entry["left"]) + int(entry["right"])) / 2.0
            if zone in ("top_right", "right_edge") and xc is None:
                pass                            # 缺 x 坐标：中性
            elif ok_zone and (xc is None or
                              xc >= ZONE_RIGHT_RATIO * screen_w):
                score += zone_bonus
            elif zone != "right_edge" or xc is not None:
                score -= zone_bonus
        except Exception:
            pass

    # 超长非可点：重罚但不否决（旧版此处 return None 整条拒配）。
    # **降档不淘汰**：overlong 候选从可信池摘出（进兜底甄别分支），
    # 但仍参与排序 —— 若它含目标词且句式无辜（营销后缀入口），放行；
    # 若不含目标词，兜底层按长句噪声处理，与旧版"优先选短"倾向一致。
    overlong = (kind in ("text", "desc")
                and len(label) > overlen_limit(t) and not clickable)
    if overlong:
        score -= _OVERLEN_PENALTY
        if is_noise_label(label, t):
            score -= _NOISE_PENALTY
    return score, overlong


def pick_best(entries, target, kind, screen_h=0, log=None, screen_w=0,
              zone=None):
    """从多匹配候选里择优（打分排序 + 超长甄别兜底）。

    entries : [{label, clickable, top, left?, right?}]（保序，最多取前 12 条）
    target  : 目标文本
    kind    : text / desc / id
    screen_h: 屏幕高度像素（0 = 未知，跳过 nav 带/zone 位置判断）
    log     : 可选回调 log(event, app="", level="INFO")
    screen_w: 屏幕宽度像素（0 = 未知，跳过 zone 右缘/右上角加分）
    zone    : tab_zone / top_right / right_edge / None（未知值忽略）
    返回    : 选中下标（平局取先）；无任何可信候选时返回 None
    """
    n = len(entries)
    if n == 0:
        return None
    scored = []                               # [(idx, score, overlong), ...]
    for i in range(min(n, 12)):
        s, ov = score_entry(entries[i], target, kind, screen_h, screen_w, zone)
        scored.append((i, s, ov))

    # 可信候选（score > floor）参与择优；全部不可信时进入超长甄别分支。
    # 兜底池排序**短者优先**：旧版「可点击优先 + 短文本优先」的倾向保留，
    # 不含目标词的说明长句与含词营销入口同池时，靠 _rank 分层再按长度收口。
    plausible = [t for t in scored if t[1] > _PLAUSIBLE_FLOOR]
    if plausible:
        best_i, best_score = plausible[0][0], plausible[0][1]
        for i, s, _ov in plausible[1:]:
            if s > best_score:                # 严格大于 -> 平局取先
                best_i, best_score = i, s
        if log is not None:
            log(f"  [{kind}]'{target}' 命中 {n} 处，择优 {best_score} 分",
                "", "DEBUG")
        return best_i

    # 兜底：只剩超长/低分候选 —— 逐条甄别，噪声句式维持拒绝（旧行为）。
    # 顺序纪律（2026-10-28 实测修正）：**优先含目标词的超长文案**，其次才是不含目标词的长句
    # —— 「立即签到 +1000火龙币」这类营销后缀在很多 App 里就是可点入口本体；
    # 「闲鱼通知：闲鱼币今日签到提醒」虽也含「签到」但属推送标题，降权靠后。
    # 同级内**短者优先**（旧版 len 升序倾向），放行后由上层 expect/落地校验把关。
    survivors = [t for t in scored if not is_noise_label(
        entries[t[0]].get("label"), target)]
    if survivors:
        def _rank(t):
            lab = str(entries[t[0]].get("label") or "")
            return (
                0 if str(target) in lab else 1,       # 含目标词优先
                1 if any(w in lab for w in _PUSH_WORDS) else 0,  # 推送标题靠后
                len(lab),                              # 短者靠前（旧倾向）
                -t[1],                                 # 分数高者优先
                t[0],                                  # 平局取先（保序）
            )
        idx = min(survivors, key=_rank)[0]
        if log is not None:
            log(f"  [{kind}]'{target}' 无常规可信候选，放行超长文案 "
                f"{str(entries[idx].get('label'))[:24]!r}（打分择优兜底，"
                f"交落地校验把关）", "", "WARN")
        return idx
    if log is not None:
        worst = str(entries[scored[0][0]].get("label"))[:24]
        log(f"  [{kind}]'{target}' 候选均为超长噪声文案（如 {worst!r}），"
            f"判为误命中", "", "WARN")
    return None
```

```python
        pkg = app_cfg.get("package")
```

```python
    def _pick_variant(self, actions: list, app_name: str, bid: str) -> list:
        """行为序列多样化：behaviors[bid] 支持「多候选模板」[[..],[..]]。

        每次执行以 _diversify_prob 概率从候选模板里随机挑一条，

        if not actions or not all(isinstance(a, list) for a in actions):
            return actions

        if n == 1:
            return actions[0]

            idx = random.randrange(n)

                          app_name, "DEBUG")
```

```python
    def _step_any_of(self, act, app_name, allow_vision=True):
        """条件分支：按顺序尝试多组动作，第一组**命中**即停。

        为什么需要：App 落地页不确定（开屏广告/活动弹窗/新手引导/上次退出的
        tab/登录态/灰度活动页都会改变落地页）。同一行为的入口可能在首屏、
        也可能只在二级页 ——
          * 写死前置步 → 堵死首屏那条路径；
          * 只写首屏锚点 → 页面漂移时全灭。
        `any_of` 让两条路径共存：先试首屏，没命中再跳「我的」重试。

        choices 中每个 choice 是一串动作；**该串全部动作都返回成功**才算命中。
        注意：分支内的定位动作应写 `optional: false`（默认），
        否则"没找到"会被当成成功，分支立刻终止。

        B7：视觉门控显式参数链 —— 只有最后一个分支 allow_vision=True，
        前面的分支是"便宜的探测"：本机 VLM 图像请求常 90s 超时，
        若探测分支也走视觉兜底，一次 any_of 可能白等好几分钟。
        嵌套（any_of 内的 any_of）时内层用当前 allow_vision 收窄。

        用法：
            - type: any_of
              choices:
              - - {type: click_first, candidates: [{type: text, value: 签到}]}
              - - {type: click_point, x: 0.9, y: 0.915, optional: true}
                - {type: think}
                - {type: click_first, candidates: [{type: text, value: 签到}]}
              optional: true      # 全部分支都没命中时是否放行
        """
        choices = act.get("choices") or []
        if not choices:
            self.recorder.log("any_of 动作缺少 choices，已忽略", app_name, "WARN")
            return False
        n = len(choices)
        for i, chosen in enumerate(choices):
            steps = chosen if isinstance(chosen, list) else [chosen]
            branch_vision = (i == n - 1) and allow_vision
            ok = True
            for a in steps:
                try:
                    if not self._dispatch_probe(a, app_name,
                                                allow_vision=branch_vision):
                        ok = False
                        break
                except StepError as e:
                    self.recorder.log(f"any_of 分支#{i + 1} 步骤失败: {e}",
                                      app_name, "DEBUG")
                    ok = False
                    break
            if ok:
                self.recorder.log(f"any_of 分支#{i + 1}/{n} 命中",
                                  app_name, "DEBUG")
                return True
            self.recorder.log(f"any_of 分支#{i + 1}/{n} 未命中", app_name, "DEBUG")
        if act.get("optional", False):
            self.recorder.log("any_of 全部分支未命中，optional 放行", app_name, "WARN")
            return False
        # B6：全 miss 非 optional 不再抛 StepError，记 WARN 返回 False
        self.recorder.log("any_of 全部分支均未命中", app_name, "WARN")
        return False

    def _step_random(self, act, app_name, allow_vision=True):
        """行为分支随机化：choices 中随机择一执行。
        每个 choice 可以是单个动作 dict，或一串动作 list。"""
        choices = act.get("choices") or []
        if not choices:
            self.recorder.log("random 动作缺少 choices，已忽略", app_name, "WARN")
            return
        chosen = random.choice(choices)
        if isinstance(chosen, list):
            for a in chosen:
                self._dispatch_probe(a, app_name, allow_vision=allow_vision)
        elif isinstance(chosen, dict):
            self._dispatch_probe(chosen, app_name, allow_vision=allow_vision)
```
