## 第一部分：共性提炼（Host 已从 12 条描述归纳，实现的设计输入，**不是**可选项）

### P1 底部导航 tab 带（10/12 个 App 存在）
- tab 数 4~5；「我的/任务/福利/领现金」类**个人中心 tab 恒在底部最右或右二**；
- tab 语义不唯一：趣列传右下=我的、UC 右下=任务、米读小说右下=任务但福利中心在「我的」中部 → **引擎必须允许多 tab 依次尝试**（any_of 已有此形态，要固化进策略）；
- 例外：快手（左上 ☰ 侧边栏）、大众点评（首页右上直落）。

### P2 签到入口三态（覆盖 12/12）
- **A 个人中心型**：tab → 任务/福利/领现金页 → 签到按钮（趣头条、UC、海马畅听、米读×2、百度地图我的也在此列）；
- **B 内容流浮球型**（家族同构）：拼多多/京东/美团三家共用「**左下数第 2 内容 tab**（多多视频/逛/视频）+ **上部最右侧边沿圆形悬浮入口**（签到提现共用）」→ 入口任务列表页内签到；
- **C 首页直落型**：百度地图【现金签到】、飞猪【能量红包】+【里程签到】、大众点评右上、快手左上 ☰ → 任务中心。

### P3 按钮文案族（分类词表的数据源）
- 签到族：`今日签到 / 立即签到 / 签到 / 签到领元宝 / 签到领金币 / 连续签到 / 得金币 / 直接领取 / 去签到`；
- 任务容器族：`任务 / 任务中心 / 福利 / 福利中心 / 领现金 / 钱包 / 赚金币`；
- tab 族：`我的 / 任务 / 福利 / 逛 / 视频 / 多多视频 / 领现金`；
- 提现族（本期只建表不配行为）：`提现 / 提现兑换 / 去提现 / 立即提现 / 连续签到旁的去提现`。

### P4 通用动作模式（引擎原语化）
1. **滚动重试**：5/12 明确「没有签到就滑动屏幕」（趣头条/拼多多/快手/海马畅听/UC）→ `click_first` 未命中时**自动上滑一轮再找**；
2. **广告打断 → 系统返回**（拼多多/京东/美团/趣头条提现）→ 与 F1 的 `back_key` 兜底复用；
3. **多弹窗清扫**（趣头条「关好几个」）→ F1 `max_rounds` 默认值需 ≥3（若 F1 已上线则其接管，本卡只需校验默认值）；
4. **时间窗**：美团提现 8-20 点 → behavior 级 `window: {start, end}`，超窗跳过并记 BLOCKED（先例，提现组启用时生效）。

### P5 右缘浮球通用规则（P2-B 的引擎化）
首屏文案候选全未命中时，探测「右缘圆形浮球」：`x∈[0.85,1.0] ∧ y∈[0.08,0.25]`（相对坐标），命中即点，进入后再找任务列表页锚点。拼多多禁截图 → 该规则是它签到的**主路径**（文案+坐标，无图）。
