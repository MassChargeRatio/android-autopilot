## 修复清单（按优先级）

### P1-1  `webui/static/app.js:234` —— any_of 分支数永不显示
- **现状**：`if (t === 'any_of' && o.branches) bits.push((o.branches || []).length + ' 路');`
- **根因**：配置字段是 `choices`，不是 `branches` → `o.branches` 恒 undefined，分支数永不显示。
- **目标**：
  ```js
  if (t === 'any_of' && o.choices) bits.push((o.choices || []).length + ' 路');
  ```
- **验证**：`grep -n "o.choices" webui/static/app.js` 且无 `o.branches` 残留；跑 `tests/test_webui.py` 相关用例。

### P1-2  `adb_backend.py:51-58`（`_run`）+ `:61-73`（`_retry`）—— 错误文本当成功
- **现状**：
  - `_run()` 异常返回 `f"[adb err] {e}"`（**非空字符串**）。
  - `_retry()` 的 `if last: return last` 把该错误文本当成功返回。
- **根因**：调用方拿 `[adb err] ...` 当成功输出继续执行。
- **目标**：错误路径**绝不返回非空成功字符串**。推荐：`_run` 的 `except` 返回 `None`（falsy）；`_retry` 的 `except` 分支把 `last` 设为 `None`（不设错误串），末尾 `return last`（可为 None）。**然后读 `shell()`/`tap()`/`swipe()`/`back()` 及所有 `_retry`/`shell` 调用方**，对 `None` 做失败判定（`if out is None: return/raise`）。若个别调用方确实依赖字符串返回，可返回 `("", False)` 元组，但**必须让失败可判定**。
- **验证**：单测 `tests/test_adb_backend.py` 全过；新增/确认一条「mock subprocess 抛异常 → 返回值判定为失败」用例。

### P2-3  `recorder.py:83-90`（`_flush_ops`）—— 吞 commit 失败丢数据
- **现状**：`except: pass` 但**无条件** `self._pending = 0`（L89）。
- **根因**：commit 失败仍清 pending，积压 ops 永久丢失。
- **目标**：仅 commit 成功才 `self._pending = 0`；失败保留 pending，下次 `_maybe_flush_ops` 重试。同步更新 docstring（L84「失败保持 except: pass 语义」已过时）。
  ```python
  def _flush_ops(self):
      try:
          self.conn.commit()
          self._pending = 0
      except Exception:
          pass  # pending 保留，下轮重试，不丢数据
      self._last_flush = time.time()
  ```
- **验证**：`tests/test_recorder_batch.py` / `test_record_flow.py` 全过。

### P2-4  `webui/routes_yaml.py:206` 与 `:295` —— 回滚误报成功
- **现状**：`return 200, {"ok": True, "action": "rolled_back", ...}`（两处）。
- **根因**：回滚是失败路径，但 `ok:true` 让前端误判保存成功。
- **目标**：两处 `"ok": True` → `"ok": False`。
- **注意**：**同步检查前端消费**（`webui/static/yaml_editor.js` / `app.js` 对 `action == 'rolled_back'` / `ok` 的判定），确保 `ok:false` 时前端正确提示回滚而非成功。若前端仅依赖 `action`，则保持 `action` 不变、只改 `ok`。
- **验证**：`tests/test_webui.py` 相关用例；手动 grep 前端 `rolled_back` 消费。

### P2-5  `webui/server.py:297-302` —— 启动任务非原子（并发竞态）
- **现状**：`active = c.jobs.active()` 检查与 `c.create_app_job(payload)` 之间无锁。
- **根因**：两请求可同时通过检查 → 同时启动两个任务（设备独占被破坏）。
- **目标**：检查 + 创建原子化。优先**在 `JobManager` 增加原子方法**（如 `try_start(payload)`，内部 `with self._lock:` 判 active + create），`server.py` 改调该方法。或 `with c.jobs._lock:` 包住检查+create（`jobs.py:303` 已有 `_lock`）。
- **验证**：`tests/test_webui.py`；并发两连发 `/api/jobs` 仅一单成功（可 mock）。

### P2-6  `human.py:140-143` —— lognormal 均值系统性偏高
- **现状**：`v = math.exp(self._rng.gauss(math.log(max(mean, 1e-6)), sigma))`。
- **根因**：lognormal 期望 = `mean·exp(σ²/2)`，σ∈[0.45,0.75] → 实际均值偏高 10~32%。
- **目标**：均值校正，使期望≈mean：
  ```python
  v = math.exp(self._rng.gauss(math.log(max(mean, 1e-6)) - 0.5 * sigma * sigma, sigma))
  ```
  同步更新注释 L139 附近（mu 含义说明）。
- **验证**：`tests/test_human_seed.py`（若测均值/分布）；或写临时脚本统计 1e5 次样本均值≈mean。

### P2-7  `adb_backend.py:111-122`（`find`）—— 子串模糊（**降级为设计权衡**）
