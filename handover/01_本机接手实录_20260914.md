### 2.4 `vision.py` VLM 后端三处硬伤（已修）
1. **复用 `requests.Session` 导致重定向死循环**：网关会下发 cookie，复用 Session 时
   从第 2 次请求起抛 `TooManyRedirects: Exceeded 30 redirects`（实测第 1 次成功、
   第 2/3 次必失败）。改为**每次独立 POST + 不自动跟随重定向**。
2. **非 JSON 返回被静默当成"未命中"**：网关常返回字面串 `User Safety: safe`
   （内容安全拦截），旧 `_parse` 找不到 `{}` 就返回 `{}`，被上层误判为"未命中"。
   现在改为**抛错并触发重试**（每个后端默认重试 3 次）。
3. **提示词缺少约束**：旧后缀未声明坐标空间、也未要求"目标不存在时返回 null"。
   已补充为：坐标基于原图像素 / 不存在必须返回 `{"x":null,"y":null}` 严禁猜测 /
   只返回一个 JSON。
   另修 `locate_by_vlm` 中 `data.get("x") or ...` 的**假值陷阱**（x=0 会被误判为缺失），
   并加了**坐标越界校验**（超出截图范围按未命中处理）。

## 3. 实测校正：VLM 兜底能力被高估（交接文档 §2.2 / §5.3 需修正）

交接文档称「未命中时返回 `{"x":null,"y":null}`」与「合成图误差约 40px」。
在**真实截图**上复测后，发现该兜底层此前**基本不可用**，且原因不是模型能力，
而是**坐标空间理解错误**（见下）。已修复，修复后误差从 ~960px 降到 **1px**。

### 3.1 根因：模型返回 0~1000 归一化坐标，工程当成像素用（关键）
该网关背后的视觉模型（`auto/best-vision`，Qwen-VL 系列惯例）默认返回
**0~1000 归一化坐标**，而旧代码直接当像素使用。证据链：

```
真实目标：主屏「设置」图标，真值 ≈ (170, 1685)   [1080x2340]
模型返回：{"x": 155, "y": 720}
误当像素 -> (155, 720)      误差 965px   ← 旧行为
换算归一化 -> 155/1000*1080=167, 720/1000*2340=1685
                            误差 2px     ← 正确解释
```

**修复**：提示词明确要求「坐标必须是 0-1000 归一化整数」，`locate_by_vlm` 里
按 `coord_space: norm1000` 换算回像素（`config.yaml` 的 `vision.vlm.coord_space`
可切回 `pixel`；若模型返回 >1000 会自动判定为像素坐标，避免误缩放）。

### 3.2 修复前后量化对比（`devtools/vlm_bench.py`，同图同目标，各 3 次）

| 用例 | 修复前 | 修复后 |
|---|---|---|
| 正向：设置图标（真值 170,1685） | 误差 965px（点错图标） | **3/3 命中，平均误差 1px** |
| 负向：抖音（本屏不存在） | 返回 (790,270) 幻觉坐标 | 3/3 正确返回 None |
| 负向：网易云音乐（不存在） | 返回 (845,378) 幻觉坐标 | 3/3 正确返回 None |
| 正向：微信图标（真值 ≈151,605） | — | 4 种提示词均命中，误差 ~8px |

### 3.3 其余已修问题（同一层）
- **`User Safety: safe` 拦截**：网关偶发（非确定性）返回内容安全串而非 JSON。
  旧代码把它静默当成"未命中"；现在抛错并重试（`vision.vlm.attempts`，默认 3 次，
  主/备两个后端共 6 次机会）。实测同一提示词重跑即可恢复。
- **重定向死循环**：见 §2.4。
- **假值陷阱**：`data.get("x") or ...` 会把合法坐标 `0` 判为缺失，已改为显式 None 判断。
- **越界校验**：换算后超出截图像素范围一律按未命中处理（防幻觉误点）。

### 3.4 使用建议
- VLM 命中后仍建议「截图复核再点」，尤其是图标级小目标（约 75~100px）。
- 大按钮（签到/提现，200px+）可直接使用，当前精度足够。
- 对拦截率高的目标，可用视觉描述替代 App 名（如"绿色对话气泡图标"），
  实测同样可用且误差相当。

## 6. 复验结论与遗留

### 6.0 实跑校准：18 个新 App（本轮新增）

按 §8 第 2 项要求，对第 2 屏新增的 18 个 App 做了**真机逐个单跑校准**。

**工具**：`devtools/calibrate.py`
- 启动 App → **自适应等待就绪**（轮询 dump，上限 70s；固定 18s 会 dump 到启动页，
  实测抖音/头条系冷启动远超 18s，导致误判"全未命中"）
- 尝试点掉常见弹窗（青少年模式/隐私政策/更新提示）
- dump UI + 截图落盘 `devtools/calib/<app>/`
- 用**工程真实的选择器语义**逐条校验该 App 每个行为的动作能否命中
- 可选二级页探针：`--probe-vlm "定位屏幕底部导航栏最右侧的『我的』标签中心"`
  —— 用 VLM 点进二级页再 dump 一页，拿到签到/提现的真实锚点

**结果**：

| 口径 | 命中率 |
|---|---|
| 首屏落地页入口命中 | **18/52 = 35%** |
| 二级页（VLM 点进底栏「我的」后）入口命中 | **22/49 = 45%** |

逐 App 明细见 `devtools/calib/SUMMARY.md`，每 App 的原始 dump/截图/报告在
`devtools/calib/<app>/`（`report.md` / `report.json` / `ui.xml` / `screen.png`
/ `ui_after.xml` / `screen_after.png`）。

这与交接文档 §6 的判断一致：新 18 App 的模板只是"基于界面特征生成"的初版，
**大部分入口锚点并不成立**。最典型的两个 App：`红果免费短剧` 3/4 基本可用，
`点淘`/`抖音`/`微博移动版` 首屏入口全不命中。

**失败原因归类**（重要，决定了怎么修）：

| 原因 | 占比 | 修法 |
|---|---|---|
| 入口在二级页（"我的"/"赚钱"），首屏根本没有该锚点 | 最主要 | 行为前加一步导航（见下） |
| 按钮是纯图片，文案在 `content-desc` 而非 `text` | 次之 | 候选加 `type: desc` |
| 文本锚点确实不存在（纯图形按钮/WebView 内） | 少数 | `click_point` + `vlm_prompt` |
| App 未启动到前台 / 卡在启动页 | 个别 | 悟空浏览器首屏已可校准（1/3），
  但二级页探针未完成；`天天快讯极速版` 落地时前台是 launcher；
  `今日看点极速版` 落地页仅 8 个节点（仍在新手引导） |

**已完成的修补**：
1. 补了 3 条经 dump 证实的 `type: desc` 候选（一淘·签到→`签到领钱`、
   今日头条极速版·签到→`开宝箱`、全民K歌·collect→`任务中心`）。
   改前备份：`config.yaml.bak-before-anchor-fix`。改后一淘首屏入口 0/3 → 1/3。
2. 验证了二级页导航方案可行：VLM 定位底栏最右「我的」标签，
   在 5 个不同 App 的截图上坐标高度一致（x≈950~973，y≈2127~2153），
   一淘实测误差 12px；点进去后各 App 入口命中率显著提升
   （一淘 0/3→2/3，今日看点极速版 0/3→2/3，抖音极速版 2/3→2/3）。
   注意：各 App 底栏写法不一（抖音是「我」不是「我的」），
   `calibrate.py` 已内置多提示词回退。

**下一步修配置的推荐做法**（对每个 App 逐条补）：
在需要二级页入口的行为最前面插一步导航，例如：

```yaml
- type: click_point
  vlm_prompt: "定位屏幕底部导航栏最右侧的『我的』标签中心"
  x: 0.9          # 视觉兜底失败时的坐标回退（比例值）
  y: 0.908
```
（`_step_click_point` 会先试视觉定位，失败才用 `x/y`；两者都填更稳。）
