## 3. 最重要的三条方法论修正

### 3.1 「单轮数字」不可作为结论

`compare_verify.py` 对比「第二批 any_of 之前 / 之后」两次单轮结果：
净变化 **-5.8 个百分点**（36/52 → 33/52）。但这**不是** any_of 变差了 ——
45 项状态持平，5 项"恶化"里 3 项是上一轮的命中项本轮漂移（星图金融 collect/bonus、
点淘 collect），2 项本就是波动项。单轮差值被噪声完全淹没。

→ 判定任何配置改动，必须看**多轮命中率**（`stability_run.py`）。

### 3.2 「离线 dump」只是线索，且 dump 本身可能是**别的 App**

跨 App 污染的真实案例：`天天快讯极速版` 的两份离线 dump，
主导包分别是 `com.vivo.doubletimezoneclock`（时钟）和 `com.vivo.gallery`（图库）——
目标 App 根本没起来。若照常分析，会得出完全错误的锚点结论。

→ 判定页面归属必须**从 dump 自身的 `package` 属性分布**读，不能信前台包名。

### 3.3 「命中」的口径必须写清楚

`withdraw` 类行为的第一个锚点就是 `我的`/`我`（流程第一步确实是点我的），
所以「withdraw 命中」**只代表找到了进入我的页的入口**，
不代表找到了提现入口。锚点层命中率是**上界**，不等于功能完整度。

→ 后续若要度量功能完整度，需要像 `probe_deep.py` 那样**穿透到真正入口**
（我的 → 提现 / 我的 → 任务中心 → 签到）。

## 4. 本轮被推翻/修正的旧结论

| 旧结论 | 本轮实测 | 处置 |
|---|---|---|
| 抖音系金币入口在「≡ 更多」侧边栏 | **错**。侧边栏是设置菜单（我的订单/我的钱包/观看历史/设置…），无金币/任务/签到 | 记录为待办，不写进配置 |

| 前台包名可判断页面归属 | 时序上会先报新包名而屏幕还是旧 App | 改为 dump 包名分布判定 |
| 蛋花免费小说二级页命中 `我的` | y=627 是页面中部，**不是底部导航** | 加底部导航带校验 |
