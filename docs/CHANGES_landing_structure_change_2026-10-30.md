# 落地校验「结构变化」兜底（2026-10-30）

## 一、先纠正上一轮的一个错判

我上一轮说「D 类 23 处里 35% 后续仍有成功点击 → 落地校验误判」，把 D 当成一类。
逐个取证后，**三个样本 app 是三种不同的病**：

| App | 日志证据 | 真实原因 |
|---|---|---|
| 京东 | `页面就绪判定: 节点=63 等待=31.4s 未稳定` | **页面没就绪就开跑**，点击落在启动页上 |
| 美团 | `页面就绪判定: 节点=234 等待=9.8s 已稳定` + `text_nodes=FAIL text_hit=[]` | 页面已就绪，但「视频」tab 没切过去（或文案变了） |
| UC | `phash 失配 dist=30/34` 判失败，紧接着下一步用另一张基准图 `dist=8` 通过 | **真·误判**：点击其实已落到任务页 |

真机复核：手动点京东「逛」tab 后 dump，`赚现金`/`领金币` 各出现 1 次 —— 说明文案确实存在，
是运行当时页面根本还没到那一页（63 节点的启动页）。

所以「35%」这个数字只是「后面还有成功点击」，不能证明是误判。已废弃该推断。

## 二、实际做了什么（只做机制，默认关闭）

新增可选的 per-step 开关：

```yaml
expect:
  phash: images/xxx/landing/ref_task.png
  accept_structure_change: true    # 默认不写 = 关闭，老配置零影响
  structure_change_min: 0.15       # 节点集合 Jaccard 差异度阈值
```

机制：开启的步骤在**点击前**存一份节点集合；phash 失配时比较点击后的节点集合，
差异 ≥ 阈值则判为已落地，并记一条**证据等级明确**的日志：

```
落地校验: phash 失配但页面结构已变化 94%，判为已落地（accept_structure_change，证据等级=结构变化）
```

两条硬限制：
1. **只救 phash 失配**，不救 `text_nodes` 失配 —— 文案没出现是有效信号，
   不能靠「页面变了」放行（京东/美团那种不救）。
2. 开关没开时不改变调用形态（`_verify_landing` 不多传参），既有测试桩签名零影响。

该步不再报「步骤失败」，也不再重试。总耗时 84s（改前 78s，差异在页面就绪 31.7s）。

## 四、这个机制救不了什么（重要）

「页面其实对、只是内容变了」那种**小差异**它救不了：

- 今日头条极速版 sign 第一步：`dist=25` → 重试 → `dist=14`，仍判失败。
  页面没换，只是内容变了，结构差异很小 → 不会触发兜底。

那种情况的正确修法是调 `phash_max_dist`（14 说明已经是同一页，只是阈值 8/10 太紧），
不是加结构兜底。
