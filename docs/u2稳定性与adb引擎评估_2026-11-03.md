# u2 atx-agent 稳定性 与 adb 纯引擎替代评估

- 日期：2026-11-03
- 范围：`device_session.py`（u2 全部调用点） / `temp/adb_core.py`（adb 纯引擎 POC）
- 结论先行，证据附后。本文档不实施改动，只做评估与门禁设计。

---

## 0. 结论（先行）

**u2 atx-agent 在本机/真机上不稳定，是「启动失败」与「前台判定失真」的直接根因；但当前它只导致 2/105 个 App 整单跳过（11-03），不是主要失分来源。adb 纯引擎技术上完全可行——u2 的 8 个操作全部有 adb 等价物，且 3 个关键原语（前台解析 / 尺寸解析 / resolve-activity 启动）已在仓库里有现成可复用的纯函数。**

**不建议立即重写。建议分两阶段：先做 `adb_backend.py` 影子后端（补齐 5 个缺口 + 防 stale dump），与 u2 并跑做对等性验证；门禁通过后再切换。** 理由：

1. u2 的失败模式是可观测、可回避的（`前台=?` 是间歇性的，多数会自愈），不是 100% 必崩；
2. adb 更原始（无元素对象、无 `.click()`），重写要重做全部定位/兜底逻辑，回归成本高；
3. 影子对等验证能先证明「adb 判定 = u2 判定」，再切换，避免盲切引入新的行为差异。

## 2. u2 → adb 能力映射（device_session.py 全部调用点）

| u2 API | 位置 | adb 等价物 | 仓库已有可复用 |
|---|---|---|---|
| `u2.connect(serial)` | :65 | `adb connect` + `-s` | `adb_core.connect()` |
| `_apply_rpc_timeout`(HTTP_TIMEOUT 300→20) | :72-89 | 无（adb 无 RPC，天然无此坑） | — |
| `d.window_size()` | :105 | `wm size` → `parse_wm_size` | `webui/data.py:342` |
| `d.press("back")` | :145,:207 | `input keyevent 4` | `adb_core.back()` |
| `d.info.get("currentPackageName")` | :152,:215,:265 | `dumpsys window` → `parse_foreground` | `webui/data.py:327` |
| `d.dump_hierarchy()` | :227,:255 | `uiautomator dump` + pull | `adb_core.dump()`（有 stale 坑） |
| `d.shell("pm list packages")` | :301 | `adb shell pm list packages` | `adb_core.shell()` |
| `d.app_start(pkg, stop=True)` | :324,:343 | `am force-stop` + `am start -n` | `adb_probe_front.py` |
| `d.app_start(pkg)` | :327 | `am start -n` | `adb_probe_front.py` |

**8 个 u2 操作全部有 adb 等价物，无一例外。** 且 3 个最关键原语（前台解析、尺寸解析、resolve-activity 启动）已是仓库内的**纯函数/脚本**，可直接借用或移植：

- `webui/data.py::parse_foreground(dumpsys_window_output)` — 用 `mCurrentFocus`/`mFocusedApp` 解析，规避了 u2 `currentPackageName` 在崩溃/切换时序下先报新包名的失真。
- `webui/data.py::parse_wm_size(out)` — `wm size` → (w, h)。
- `handover/02_适配脚本/adb_probe_front.py` — `cmd package resolve-activity --brief` 取启动组件 → `am start -n` → `dumpsys window` 确认前台。

## 3. adb_core.py 现有能力与缺口

`temp/adb_core.py`（3.9 KB，族A 探针，非全引擎）：

**已有**：`connect / shell / cold_start(monkey) / tap / swipe / back / dump / shot / read_color / texts / find / center`。

**缺口（替换 u2 前必须补，共 7 项，按严重度排序）**：

| # | 缺口 | 严重度 | 说明 |
|---|---|---|---|
| 1 | `foreground()` | **高** | 当前无。`前台=?` 的根因判定就靠它；直接移植 `parse_foreground` |
| 2 | stale dump 防护 | **高** | `dump()` 只查 `>500 字节`，**不识别**「3 次 dump 字节数相同=旧 `_p.xml` 工件」陷阱。需记录连续字节数，3 连相同则重 dump |
| 3 | 精确冷启动 | 中 | 现用 `monkey`（只发 LAUNCHER intent，可能进错组件）；改 `resolve-activity` + `am start -n` |
| 4 | `click_text()` | 中 | `find()+center()` 已有，缺组合封装 |
| 5 | `scroll_to_find()` | 中 | watch/bonus 需要滑动直到命中 |
| 6 | `window_size()` | 中 | 归一化坐标依赖，移植 `parse_wm_size` |
| 7 | 重试/退避 | 中 | `uiautomator dump`/`input` 偶发挂起；需等价于 u2 `rpc_retries=2, rpc_backoff=0.8` 的兜底 |

## 4. 分阶段落地建议

### 阶段 A（本轮可做）：`adb_backend.py` 影子后端 + 对等验证
1. 新建 `adb_backend.py`：补齐缺口 1-7（前台/dump防stale/resolve启动/click_text/scroll_to_find/window_size/retry）。
2. **不改** `device_session.py`（u2 照常）。
3. 写 `temp/adb_parity_probe.py`：对快手/抖音/美团 3 个 u2 高危 App，每 App 依次用 u2 与 adb 各取一次前台包名 + dump 节点数 + 首屏文本集，比较一致性。
4. 门禁：**对等率 ≥ 95%**（前台包名 100% 一致；dump 文本集 Jaccard ≥ 0.9）。

### 阶段 B（门禁通过后）：切换
5. 若门禁过，把 `device_session.py` 的 u2 调用点替换为 `adb_backend` 等价方法（保持同一接口签名，返回类型对齐：`window_size` 仍回 plain tuple、`dump` 仍回 str、`info` 换成 `foreground()`）。
6. u2 保留为 `fallback=True` 配置项，可一键回退。
7. 跑 `verify_live` 全量 + 单元测试，对照 11-02 基线（77 app / 3 跳过）确认无行为回归。

## 5. 风险与规避

| 风险 | 规避 |
|---|---|
| adb `uiautomator dump` 本身偶发失败（返回空/超时） | 缺口 2 + 7：stale 检测 + 重试退避；失败时走 `shot()` 截图佐证，不盲信 dump |
| 盲切引入行为差异（adb tap vs u2 tap 落点） | 阶段 A 影子对等验证，先证一致再切 |
| adb 无元素对象，重写定位/兜底成本高 | 只换原语层，`behavior_runner`/`locator` 的 XML 解析逻辑复用（它已基于 dump 字符串，不依赖 u2 元素对象） |
| `foreground()` 时序失真（切屏瞬间） | 用 `dumpsys window` 的 `mCurrentFocus` 而非 `mFocusedApp` 优先，与 webui 现有解析一致 |

## 7. adb dump 取数规范（族级规则，2026-11-04 Q1 沉淀）

> 来源：Q1 §5.21.1-⑤ / §5.21.4-4。这四条正是**历史「parity 0 字节 OPEN」的全部成因**，升为族级规则，所有 adb `uiautomator dump` 取数必须遵守。

| # | 规则 | 成因（违反的坑） |
|---|---|---|
| 1 | dump 落 **`/data/local/tmp/`**（如 `dy.xml`），勿落 `/sdcard` | `/sdcard` 上 dump 恒 **0 字节**（命令回显 "UI hierchary dumped to" 但文件为空/不存在）——parity 0 字节 OPEN 的直接根因；改落 `/data/local/tmp` 后立即正常（104375 B） |
| 2 | 取数用 **`adb pull` 子进程**（非 shell 内嵌命令） | `adb shell pull` 不成立：pull 必须走独立 `adb pull` 子进程，当 shell 命令执行时本地永远拿不到文件 |
| 3 | 包名取**众数**（`package="..."` 出现最多者），勿取首个 | u2 多窗口 dump 的日志顺序：首个 `package` 常是 overlay（如 `com.vivo.upslide`），取首个会误拉错包（曾误拉「抖音极速版」） |
| 4 | dump **≥2 次重试** + 点屏保 idle 后再 dump | dump 首轮可能报 `ERROR: null root node returned by UiTestAutomationBridge`，第 2 次重试即成功；点屏（暂停播放）可保 idle，降低失败 |

> 关联：`adb_backend.py` 已内置 stale 保护（连续 3 次同字节数=陈旧产物）+ rpc 重试退避（rpc_retries=2 / rpc_backoff=0.8），与本规范共同构成 dump 取数的可信底座。
