# ANTI_DETECTION — 反机器人检测威胁面与能力边界

> AUTOP-FEAT-2026-10-20 F2 ｜ 落盘 2026-10-21 ｜ Host 自执行
> **本文档的纪律是诚实**：不夸大可缓解项、不隐藏不可缓解项。每项标注
> 「可缓解 / 部分缓解 / 不可缓解」，并写清具体动作或写清为什么做不到。
> 本工程**不引入任何第三方改机/root/hook/虚拟机框架**（红线，越界即打回）。

## 0. 总览：本项目用什么姿势被看见

本项目的交互链路是：PC 端 Python → adb（无线调试 5555 端口）→
uiautomator2 → 设备。App 侧能看到的一切都从这个链路漏出去。
**核心判断：adb/u2 链路的痕迹不可能完全隐藏**（开发者选项状态、
`service.adb.tcp.port`、uiautomator2 server 包名都是系统级事实），
所以反检测的重心放在**行为时序与输入模式**这两类 App 业务层可观测、
且本项目真正能改善的维度上。

## 1. 逐项威胁面

### 1.1 开发者选项 / USB 无线调试开启（`ADB_ENABLED`、`service.adb.tcp.port`）

- **检测方可见性**：App 读系统设置即可见（`Settings.Global.ADB_ENABLED`、`service.adb.tcp.port` 非空即无线调试中）。
- **现状**：真机 192.168.1.54:5555 正是无线调试模式，开发者选项已开。
- **可缓解性**：**不可完全隐藏**（系统级事实，无 root 改不了）。降低相关性的手段：
  - 错峰执行（作息窗口 07:30-23:00 + 启动抖动，已实现于 `human.py`）；
  - 短会话：单次任务跑完即退，不长时间挂着 server（`close_naturally` 后由上层决定是否停 u2 server）。
- **本项目动作**：保持错峰；不尝试伪造系统属性（无 root，且属改机行为，越界）。

### 1.2 已知自动化包名/服务（uiautomator2 server `com.github.uiautomator` 等）

- **检测方可见性**：部分 App 会扫已安装包列表/运行中服务。
- **现状**：u2 连接后 server APK 必然在设备上（注入式 u2 的标准形态）。
- **可缓解性**：**不可隐藏 server 本身**。可缓解的是**暴露时长**：
  - 理论上 `d.uiautomator.stop()` 可在用完后停掉 server —— **未实测**（注入式 u2 下该 API 的可用性存疑，停不掉反而留异常）。如实记录：**本期不做**，待实测后再评估。
  - 现行缓解 = 任务结束即断开（不维持长连接）、单设备单会话。
- **诚实结论**：包列表类检测对本项目**无效防御**，靠 1.1 的错峰与 1.3-1.5 的行为层稀释。

### 1.3 时序规律（固定间隔、固定顺序、全天均匀分布）

- **检测方可见性**：服务端埋点可见（点击间隔直方图、每日执行时刻分布）。
- **可缓解性**：**可缓解**（这是本项目的主战场）。
- **本项目动作**（均已实现，`human.py`）：
  - 动作用对数正态分布采样（多数快、偶尔慢的长尾形态，`use_lognormal` 默认开）；
  - 启动时刻随机偏移（`run_jitter_seconds`，生产用；回归用 `--fast` 跳过）；
  - **F2 新增限流长停**：每 `cooldown_every`（默认 12）次点击强制一次
    `cooldown_seconds`（默认 20s，0.7~1.3 倍抖动）长停，打断机械节奏；
  - 作息窗口限制在人类活跃时段。

### 1.4 输入模式（无误触、无回退、无乱看、坐标过于居中）

- **检测方可见性**：客户端可采集触摸事件流。
- **可缓解性**：**可缓解**。
- **本项目动作**：
  - 点击坐标抖动 `tap_jitter_px`（已有）；
  - **F2 新增误触-回退** `mistake_prob`（默认 0.05）：以小偏移
    （±160px 内）先点错位置，愣神 0.25~0.7s，再点正确位置；
    **取舍记录**：偏移刻意取小——大幅乱点可能真的点进别的功能改变页面，
    "像真人"必须让位于"不破坏流程"，此为保守值；
  - **F2 扩展乱逛** `wander_probability`（默认 0.10）：行为间隙小概率
    轻滑 / 浏览式连滑 2-3 次 / 发呆三选一（原有 maybe_wander 的扩展）；
  - 贝塞尔轨迹 + 慢-快-慢速度轮廓 + 末段微颤（`human_trajectory.py`，已有）。

### 1.5 设备农场特征（机型/分辨率/语言/时区单一）

- **检测方可见性**：服务端画像。
- **可缓解性**：**不可缓解**（单机单账号是小规模自用形态，不是农场；
  文档说明即可，伪造机型信息属改机，越界不做）。

### 1.6 验证码/风控命中后的应对

- **检测方可见性**：风控系统直接弹验证码/限制。
- **可缓解性**：**不可"绕过"** —— 本项目明确**不尝试破解风控**（红线）。
- **本项目动作**（F2 新增）：验证码 step 求解失败 → `captcha_cooldown`
  （默认 300s，0.8~1.2 倍抖动）会话级冷却，期间**不重试猛点**，
  之后交上层决定去向（通常该 App 当日不再尝试）。
- **诚实结论**：命中风控=本时段该账号已被标记，冷却只是不再刺激对方，
  不是"洗白"。

## 2. 能力矩阵（速查）

| 信号 | 可缓解性 | 本项目手段 | 状态 |
|---|---|---|---|
| 开发者选项/无线调试 | 不可完全隐藏 | 错峰+短会话（降相关性） | 已有 |
| u2 server 包名 | 不可隐藏 | 缩短暴露时长；`uiautomator.stop()` 未实测、本期不做 | 部分缓解 |
| 固定间隔/顺序 | 可缓解 | 对数正态延迟+启动抖动+**限流长停(F2)** | 已有+F2 |
| 触摸输入过于完美 | 可缓解 | 坐标抖动+**误触回退(F2)**+**乱逛扩展(F2)**+贝塞尔轨迹 | 已有+F2 |
| 单设备单画像 | 不可缓解 | 文档说明（自用形态，非农场） | 说明 |
| 验证码风控 | 不可绕过 | **求解失败冷却(F2)**，不猛点 | F2 |
| 截图/录屏检测 | 可减少面 | 视觉兜底默认关（`vision: false`），仅必要时截屏 | 已有 |

## 3. 配置（config.yaml `anti_detection` 段）

```yaml
anti_detection:
  enabled: true
  mistake_prob: 0.05        # 误触-回退概率
  wander_probability: 0.10  # 乱逛概率（覆盖 human 段同名值）
  cooldown_every: 12        # 每 N 次点击强制长停
  cooldown_seconds: 20      # 长停秒数（0.7~1.3 抖动）
  cooldown_on_captcha: 300  # 验证码失败会话冷却
```

**取值纪律**：所有概率类参数由 `human.py` 的统一随机源
`self._rng`（seed 可复现）消费，禁止裸 `random.*`；同 seed 下整条
动作序列可复现（`tests/test_anti_detection.py` 锁定该性质）。

## 4. 明确不做（越界清单）

- 不用任何第三方改机/root/hook/Xposed/虚拟机框架；
- 不伪造设备信息（机型/分辨率/IMEI/安卓ID）；
- 不尝试识别并破解业务风控/验证码（滑块求解是既有能力，失败即冷却，不升级对抗）；
- 不隐藏/停用 adb 调试本身（无 root 也做不到，且属对抗系统安全机制）。

## 5. 已知残留风险（如实记录）

1. 无线调试状态对 App 可见 —— 单机自用场景下的**既有事实**，本文档不假装它不存在；
2. 误触-回退的小偏移仍有概率点中相邻可点区域，导致该次点击后页面与预期不符 —— 
   由上层 any_of/optional 容错兜底，概率上可接受；
3. `d.uiautomator.stop()` 未实测，server 暴露时长的缓解暂依赖"任务级短会话"。
